# hebreaks figures

## Current 10,000-realization results

The default run root is `runs/hebreaks_results_10k`. To verify the completed
ensembles and regenerate all five Monte Carlo result figures and four tables:

```sh
make -C plotting/projects/hebreaks test publish-results PYTHON="$PWD/.venv/bin/python"
make -C /Users/carmeloevoli/Work/overleaf/hebreaks.paper
```

`make results` (also the default `make`) generates without publishing.
All publication targets require 10,000 consecutive seeds by default.
`SEEDS=N` explicitly changes that target; update the manuscript if publishing
a different sample size. No simulations are launched by these targets.
The individual targets are `publish-halos`, `publish-variations`,
`publish-low-rate`, and `publish` (associations).

`plot_population_results.py` now handles both low-rate and association results.
It verifies completion checksums, population tables, shared physics/builds,
and the 100 Myr, exactly cutoff-free prescription. The independent association
control includes stellar spreading and is distinct from `halos_H4`.
Summaries include 2500/5000/10000 prefix checks, per-seed provenance, exact
binomial intervals, and association population means. For zero exceedances,
the one-sided 95% probability limit is 0.00029953, not zero.

Figures 1--5 and the experimental curvature analysis do not depend
on these enlarged ensembles and are not regenerated by `publish-results`.
The single-catalogue participation illustration has its own diagnostic and
publication target (see below); it is not another 10,000-realization ensemble.
The sections below document individual diagnostics and the original 1,000-run
production commands; use the overnight runner for the current full ensemble.
Never rebuild executables during production or an extension of that run.

## Figure 2: escape times and Xie source snapshot

Generate the small diagnostic tables from the **current C++ implementation**,
using the dedicated config (commands from the repository root):

```sh
cmake --build build --target inspectEvents inspectPropagation -j 4
build/inspectEvents configs/hebreaks/figure2_xie2024.ini --outdir runs/hebreaks_figure2
build/inspectPropagation configs/hebreaks/figure2_xie2024.ini --outdir runs/hebreaks_figure2
make -C plotting/projects/hebreaks figure2
make -C plotting/projects/hebreaks publish-figure2
```

The last command publishes only `gryphon_escape.pdf` and `gryphon_spirals.pdf`.
No flux ensemble or association statistics are regenerated. Outputs, seed, and
resolved parameters are retained under `runs/hebreaks_figure2/figure2_xie2024/`.

Both panels use gryphon.mplstyle and no grid. The escape panel reads the C++
diffusion diagnostic with D0/H=0.42 kpc/Myr at 1 TeV and delta=0.36, verifies it
against H^2/(2D), and scales it to H=2,4,8 kpc at fixed D/H. At 1 TeV these
give 2.38095, 4.76190, and 9.52381 Myr.

The map shows the actual light-cone-selected source events over 1 Myr, at a
Galactic rate of 2/century, using Xie2024 (five spiral components with unequal
weights and a central component). It uses the simulation's R_sun=8.5 kpc and
corresponding rescaling/rotation of the Xie geometry described in Appendix A.
The Sun-centred output coordinates are translated back to Galactocentric
coordinates, placing the Sun at (8.5,0) kpc. No independent Python sampler,
old Steiman arm curves, or bar is overlaid. Horizon circles have radii sqrt(2)H
and share the halo colors of the left panel; they are characteristic scales,
not source-selection cuts. The 1 Myr window is illustrative, not the longer
history used to compute the proton spectra.

`make test` includes analytic escape-time, horizon, and coordinate checks.
Use `PYTHON=../../../.venv/bin/python` from this directory if the default
Python lacks scipy, which is needed by the existing feature-statistics tests.

## Ten-Myr association snapshot

The two matched diagnostic configurations change only the association fraction
and run name. Generate their actual C++ events (seed 0, without scanning seeds):

```sh
cmake --build build --target inspectEvents gryphon_tests -j 4
build/inspectEvents configs/hebreaks/snapshot_independent.ini --outdir runs/hebreaks_snapshots
build/inspectEvents configs/hebreaks/snapshot_clustered.ini --outdir runs/hebreaks_snapshots
make -C plotting/projects/hebreaks snapshot PYTHON="$PWD/.venv/bin/python"
make -C plotting/projects/hebreaks publish-snapshot PYTHON="$PWD/.venv/bin/python"
```

The last command publishes only `gryphon_association_snapshot.pdf`, not the
ensemble statistics or Figure 2. The plot uses gryphon.mplstyle with no grid,
equal scales and marker sizes. The fixed view is the face-on square
`|x-x_sun| <= 2 kpc`, `|y| <= 2 kpc`, including all heights. Both cases retain
Xie2024 centres, 2 SNe/century, 100 progenitors per association, 30 pc initial
one-dimensional size and 3 km/s velocity dispersion. There is no count
renormalization or change to the transport/injection models.

The 10 Myr outputs have separate run names `snapshot_independent_10myr` and
`snapshot_clustered_10myr`, preserving the original 1 Myr diagnostic tables.
The plot rejects the old time window rather than relabelling its events.

The 10 Myr window selects **explosion ages**, with parent births extending back
to 58 Myr; it does not select associations born in the last 10 Myr. Both cases
use the same displacement and light-cone selection, including the independent
control. `inspectEvents` additionally writes `event_origins_000000.txt` and
`population_000000.txt` for association-enabled configs. Positions `x,y,z` are
Sun-centred; parent `centre_x,centre_y,centre_z` are Galactocentric. Parent ID
0 denotes independent field events. Positive IDs identify a common birth
time and centre, not an observed catalogue object.

All retained events in the view are plotted. To avoid an unreadable palette,
six parent associations are highlighted, selected deterministically by their
3D centre distance to the Sun among those with centres in the view and at
least two visible events. Crosses are parent centres, not additional SNe;
unhighlighted grouped events remain grey. No trajectories are shown. The
figure illustrates accumulated explosion positions, not CR flux weights or
fluctuation significance. In particular, the 10 Myr display window is longer
than the escape time in the 10--100 TeV feature range for the adopted H=4 kpc.
`association_snapshot.json` records the selection, counts and seed. Optional
metadata collection has no extra random draws or storage cost when disabled;
C++ tests verify exact equality of events and RNG state with/without it.
Python tests check the shared window, parent selection and metadata consistency.

## Figure 5: individual proton realizations

Regenerate both halo models with the current C++ implementation, then plot and
explicitly publish just the two Figure 5 panels:

```sh
cmake --build build --target runAnisotropy -j 4
python3 scripts/run_figure5.py
make -C plotting/projects/hebreaks test figure5 PYTHON="$PWD/.venv/bin/python"
make -C plotting/projects/hebreaks publish-figure5 PYTHON="$PWD/.venv/bin/python"
```

Despite its name, `runAnisotropy` is a config-driven wrapper around the same
galaxy, injection and `CosmicRays` classes as `runModels`; Figure 5 reads only
its flux column. No physics or C++ defaults are changed by this workflow.
The dedicated `figure5_H2.ini` and `figure5_H4.ini` configs differ only in halo
height and name: Xie2024, D0/H=0.42 kpc/Myr, delta=0.36, gamma=2.34,
Emax -> infinity, 2 SNe/century, identical 10^50 erg injections above 10 GeV,
100 Myr history, 64 logarithmic bins from 100 GeV to 1 PeV. There are no
synthetic associations or energy/index scatter. The 100 Myr history is about
18 and 9 escape times at 100 GeV for H=2 and 4 kpc, respectively.
For `GalacticRandom`, `injemax=0` requests an exactly uncut power law, with
analytic energy normalization to infinity, not an approximate large cutoff.
The injection-energy lower bound remains 10 GeV. This limit requires gamma>2.

All ten seeds 0--9 are plotted for each halo, with the same color assigned to
each seed in both panels. The dashed line is the pointwise median of these
**ten displayed spectra**, not a large-ensemble estimate. There is no selection
for strong features, smoothing, or per-realization normalization. These
illustrations cannot measure rare-tail probabilities.

As in the original figure, a single scalar per halo sets the arithmetic mean
of E^2.7 times the median spectrum on the logarithmic grid to 10^4 in the
displayed units. This preserves the relative amplitudes and shapes of all
realizations. The exact display factors and corresponding common efficiencies
are recorded in `figure5_summary.json` for the current run.
This is a display convention, not a fit of the source power to the data.
The CALET, DAMPE and CREAM kinetic-energy tables are shown without shifts,
using total errors in quadrature, explicit experiment zorder and thicker caps.
Both panels have identical axes, gryphon style and no grid.

The new spectra are isolated under `runs/hebreaks_figure5_uncut/figure5_H{2,4}/`.
The previous 10 PeV-cutoff outputs remain in `runs/hebreaks_figure5/` and are
not overwritten or used by the updated plot.
The runner saves config text, executable/library hashes, logs, seeds and
per-file completion checksums. It refuses to mix changed builds/configs with
existing results; use a new `--outdir` after such changes, then set
`GRYPHON_RUNS` to that directory for plotting. A rerun skips verified completed
seeds. `figure5_summary.json` records the inputs and exact display factors;
publishing copies it to the paper's `modelstats/`, together with the two PDFs
in `figures/`. The archived residual/slope ensembles remain untouched.

The paper's variable-index benchmark is also now cutoff-free: `runModels`
sets parent mean 2.34 and width 0.30, using rejection sampling to condition
the Gaussian on gamma>2. It does not clamp draws to 2, retune the parent mean,
or normalize divergent spectra. The resulting population mean and standard
deviation are 2.412255 and 0.245382. Existing finite-cutoff behaviour is retained
for other callers with `injemax>10 GeV`; no global default is changed.
`test_injection_curvature.py` checks the appendix's exact truncated-Gaussian
energy-normalized average against quadrature and its curvature against both
finite differences and the flux-weighted index variance. The archived
variable-index ensemble is not used by the new source-variation workflow below.

## Identical-source halo ensemble: first results subsection

Run the current model for H=2,4,8 kpc, then generate and explicitly publish
the two-panel residual/slope figure and the machine-readable results:

```sh
cmake --build build --target runAnisotropy -j 4
python3 scripts/run_halos.py --seeds 1000
make -C plotting/projects/hebreaks test publish-halos PYTHON="$PWD/.venv/bin/python"
```

`configs/hebreaks/halos_H{2,4,8}.ini` changes only halo height and run name.
All three use independent Xie2024 source events (not a spatially uniform
disk), identical uncut index-2.34 injections of 10^50 erg above 10 GeV,
2 explosions per century, D(1 TeV)/H=0.42 kpc/Myr, and delta=0.36.
Energy/index scatter and synthetic associations are disabled. The common
100 Myr history exceeds ten escape times even at 1 TeV for H=8 kpc. The
energy grid is 48 logarithmic bins from 1 TeV to 1 PeV. The production
sampler retains its one-year Bernoulli time steps and causal event selection.
No old finite-cutoff spectra or synthetic smooth background are substituted.

The consecutive, unselected seeds 0--999 give independent histories within
each halo sample, and the same histories are used across halos. The runner
uses three parallel models, four flux threads each by default, with seeds
serial within a model. Outputs are isolated under `runs/hebreaks_halos_uncut`.
Config text and executable/library hashes are saved in `halos_manifest.json`;
each completed flux file has a checksum marker. Rerunning skips verified
outputs and recovers incomplete seeds. Increasing `--seeds` extends the same
sample; after a physics/build change use a new `--outdir` instead. Plot with
`GRYPHON_RUNS` pointing to that new directory. For a different sample size,
call `plot_halos.py --seeds N` explicitly; the publication target deliberately
requires the agreed 10,000-seed sample, so it cannot silently publish a shorter
partial run. Update the manuscript sample size if publishing an extension.

The left panel uses the largest absolute fractional residual in 10--100 TeV
relative to an **unweighted log-flux versus log-energy** power-law regression
over 1 TeV--1 PeV. The right panel uses the maximum minus minimum running
index in 10--100 TeV; centered five-bin regressions span 0.2553 dex and the
two edge bins on each side are excluded. All bins in the fit have equal
weight. There is no per-realization normalization, smoothing outside the
stated running window, spectral-feature selection, or measurement noise.

The gray 0.16--0.19 residual and 0.20--0.35 slope bands are **data-motivated
amplitude benchmarks**, not confidence intervals for these ideal-spectrum
estimators. Experimental fits use different energy coverage and uncertainty
weighting, and asymptotic broken-power-law indices are not running-index
excursions. The survival curves therefore do not give data-fit p-values or
the probability of reproducing a coherent break.

Curves end at the largest observed excursion. Shading retains pointwise
exact two-sided 95% Clopper-Pearson intervals even for zero counts; these
are not simultaneous confidence bands. A dotted line marks 1/N. The JSON
also records **one-sided** 95% limits for zero counts, `1-0.05**(1/N)`;
these differ from the upper endpoints of the two-sided plotted intervals.
For N=10,000 the zero-count one-sided limit is 0.00029953, not zero;
10^-4 corresponds to only one event and smaller probabilities are unresolved.
The same seeds across halos mean that the halo estimates are correlated;
the marginal binomial intervals do not establish a between-halo significance.

`halos_summary.json` records parameters, input hashes, percentile/threshold
statistics, and fixed-prefix (N/4, N/2, N) checks of sample-size stability.
`halos_statistics.txt` retains each realization's two statistics.
`halos_table.tex` supplies the manuscript table directly from the verified
outputs. Publishing copies these to the paper's `modelstats/` and only the
new `gryphon_halo_statistics.pdf` to `figures/`; legacy figures remain intact.
This workflow does not regenerate the variable-source, low-rate, or
association ensembles; `publish-results` updates all four groups.

## Source-to-source variations: second results subsection

Using the **same executable/library build as the halo ensembles**, run the
two independent injection-variation cases at H=4 kpc:

```sh
python3 scripts/run_variations.py --seeds 1000 --threads 6
make -C plotting/projects/hebreaks test publish-variations PYTHON="$PWD/.venv/bin/python"
```

Do not rebuild while a simulation is running. The runner checks the H=4
reference build fingerprint before starting and checks its own fingerprint
before/after each new seed. If the physics/build changes, regenerate matched
ensembles in new directories instead of mixing them with the reference.
`configs/hebreaks/variations_energy.ini` changes only `varyenergy`; its
GalacticRandom implementation draws a 0.54-dex log-normal source energy,
with median 10^50 erg above 10 GeV. The mean luminosity is consequently
larger by 2.166 times; it is not kept fixed. `variations_index.ini` instead
enables `varyslope` with parent mean 2.34 and width 0.30, conditioned on
gamma>2 by rejection sampling, at fixed injected energy. Both use an exactly
absent cutoff (`injemax=0`), not a large finite surrogate.

Outputs live in `runs/hebreaks_variations_uncut/{variations_energy,variations_index}`.
Each case has 1000 consecutive unselected seeds, with the same catalogues as
the already completed `halos_H4` reference. Catalogue generation precedes
the random injection draws. The Xie distribution, rate, halo, diffusion,
100 Myr histories and 48-bin energy grid are unchanged. Models run in
parallel, seeds serially within each model; completed outputs have checksum
markers and `variations_manifest.json` provides config/build provenance.
Rerunning resumes safely; increasing `--seeds` extends the unselected sample.

`plot_variations.py` verifies all files and matched shared parameters/builds,
then applies the **same** residual and five-bin running-index statistics,
benchmark ranges and pointwise binomial intervals as `plot_halos.py`. Raw
statistics are unchanged by plotting normalization; no continuum or ensemble
median is subtracted. The index-scatter statistics therefore include smooth
ensemble curvature as well as stochastic features, and are not probabilities
of a localized softening. An analytic homogeneous continuous-source limit,
using the exact truncated, fixed-energy average from the appendix, is recorded
in the JSON as a diagnostic only. A width of 0.30 does not imply curvature
0.30^2 in this energy-normalized truncated prescription.

Two figures are produced: `gryphon_variations_spectra.pdf` shows pointwise
medians and central 90% intervals for E^2.7 J and the running index;
`gryphon_variations_statistics.pdf` shows the two survival functions. One
energy-independent scalar per model normalizes the median spectrum at
1 TeV; individual realizations are never separately normalized. Quantiles
of the running index are computed from the indices of individual spectra,
not derivatives of flux-quantile curves.

Publishing copies only these two PDFs and `variations_summary.json`,
`variations_statistics.txt`, `variations_table.tex` into the paper. The JSON
contains input/analysis hashes, exact per-seed statistics provenance, spectrum
and index quantiles, diagnostics of the median spectrum, and N/4, N/2, N
fixed-prefix checks. For a non-publication preview, use
`plot_variations.py --seeds N --output /path/to/preview`; the publish target
requires the full 10,000 realizations. Legacy source-variation outputs are
retained but no longer used by the rewritten subsection. Low-rate and
association results are not regenerated by this workflow.

## Effective source number: one matched catalogue

`inspectEffectiveSources` evaluates `(sum I_i)^2 / sum I_i^2` from individual
source intensities with the production galaxy, injection, and propagation
implementations. The streaming accumulator rescales by the largest weight
to avoid underflow when squaring dimensional fluxes. It does not modify the
production `CosmicRays` class or add work to the overnight executable.

Build in a **separate directory**, retaining the compiler and Release settings
of the production build; do not overwrite its binaries or library fingerprints:

```sh
cmake -S . -B build-effective-sources -DCMAKE_BUILD_TYPE=Release \
  -DCMAKE_CXX_COMPILER=/opt/homebrew/bin/aarch64-apple-darwin25-g++-15 \
  -DBUILD_EXPERIMENTS=OFF -DBUILD_DIAGNOSTICS=ON -DENABLE_TESTING=ON
cmake --build build-effective-sources --target inspectEffectiveSources gryphon_tests -j 6
build-effective-sources/gryphon_tests --gtest_filter='Participation.*'
python3 scripts/run_effective_sources.py
make -C plotting/projects/hebreaks test publish-effective-sources PYTHON="$PWD/.venv/bin/python"
```

The runner uses frozen configurations from `runs/hebreaks_results_10k` for
`halos_H4`, `variations_energy`, and `variations_index`, and writes only under
`runs/hebreaks_effective_sources`. Seed 0 is fixed in advance, not selected
by spectral features. The three diagnostics are serial internally and run in
parallel across models. Each keeps the same RNG ordering as `runAnisotropy`.
Completion checksums and build/config manifests permit verified reuse; a
changed build requires a new `--outdir`. Neither the original ensemble nor
its completion markers are modified.

`plot_effective_sources.py` verifies matching catalogue fingerprints and
counts, shared parameters/builds, physical bounds on the participation
number, and agreement of each total spectrum with the original seed-0 flux
to relative tolerance 1e-8 (the original tables have nine significant digits).
The catalogue fingerprint is FNV-1a over ordered native double bytes; it is
only a same-platform equality check, not a portable or cryptographic format.
The figure shows N_eff and ratios to the identical-source case, with the
10--100 TeV search interval shaded. No ensemble percentiles or feature
probabilities are inferred from this single catalogue.

Publishing copies `gryphon_effective_sources.pdf` and
`effective_sources_summary.json` to the paper. The summary retains all
48-bin curves, checksums, source count, catalogue fingerprint, and logarithmic
interpolations at 1, 10, 100, and 1000 TeV for interpreting the figure.
